# Contributing Guide

Thank you for contributing to the Farmer Marketplace project.

Please follow the guidelines below to maintain a clean and consistent codebase.

---

## Branch Naming Convention

Use the following branch naming format:

```text
feature/<feature-name>
bugfix/<bug-name>
docs/<document-name>
chore/<task-name>
```

### Examples

```text
feature/navbar
feature/login
feature/product-list

bugfix/login-validation

docs/readme

chore/project-setup
```

---

## Commit Message Convention

Use meaningful commit messages.

### Format

```text
feat: add new feature
fix: fix a bug
docs: update documentation
style: formatting changes
refactor: improve existing code
test: add or update tests
chore: maintenance tasks
```

### Examples

```text
feat: create responsive navbar

feat: add login page UI

fix: resolve login validation issue

docs: add contributing guide

chore: setup project structure
```

---

## Development Workflow

```text
Checkout develop
        ↓
Pull latest changes
        ↓
Create feature branch
        ↓
Implement feature
        ↓
Commit changes
        ↓
Push branch
        ↓
Create Pull Request
        ↓
Code Review
        ↓
Merge into develop
```

---

## Coding Standards

- Use meaningful variable and function names.
- Follow the project folder structure.
- Keep components reusable.
- Write clean and readable code.
- Remove unused imports and variables.
- Use proper indentation and formatting.
- Write meaningful commit messages.

---

## Pull Request Checklist

Before creating a Pull Request, make sure:

- [ ] Project builds successfully.
- [ ] Code is tested.
- [ ] No unnecessary files are included.
- [ ] Documentation is updated (if required).
- [ ] Code follows the project standards.
